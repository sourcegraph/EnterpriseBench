# Mining Candidate Review Checklist

This checklist guides human review of candidates generated by `pipeline.py`.
Each candidate directory contains `task.toml`, `instruction.md`, and `metadata.json`.

## Pre-Review Triage

Before detailed review, quickly filter candidates:

- [ ] **Confidence**: Is `metadata.json → confidence` "high"? Medium candidates need extra scrutiny.
- [ ] **Ecosystem**: Does this ecosystem need more tasks? Check current distribution with `scripts/validation/task_mix_validator.py`.
- [ ] **Duplicate**: Is this breaking change already covered by an existing task in `benchmarks/`?

## Detailed Review

### 1. Ground Truth Verification

- [ ] **Fix PR exists**: Open `metadata.json → downstream_fix_pr` and verify it addresses the breaking change.
- [ ] **Fix commit**: If `downstream_fix_commit` is provided, verify it's the right commit (not a merge commit).
- [ ] **Scope check**: Fix touches 2–20 files. Too few = trivially easy. Too many = expert-only or too broad.
- [ ] **Single ground truth**: The fix is contained in one commit/PR, not spread across multiple PRs over months.

### 2. Reproducibility

- [ ] **Pin upstream**: Clone upstream repo at `upstream_version` tag. Verify the breaking API is present.
- [ ] **Pin downstream**: Clone downstream repo at `downstream_affected_version`. Verify it compiles/works with the *previous* upstream version but breaks with the new one.
- [ ] **Fix applies cleanly**: Check out the fix commit and verify it resolves the build/test failure.

### 3. Task Quality

- [ ] **Prompt clarity**: Read `instruction.md`. Is the task unambiguous? Does it avoid giving away the answer?
- [ ] **Difficulty**: Does estimated difficulty match the actual effort? (medium: 2–3 files, hard: 4–8, expert: 9+)
- [ ] **Checkpoints**: Are checkpoint verifiers implementable? Each should have concrete grep/test patterns.
- [ ] **Ground truth files**: Fill in `(needs human review)` entries in `task.toml → ground_truth.required_files` with actual file paths.

### 4. CRNT Validation

- [ ] **Run CRNT**: `python3 scripts/validation/crnt_validator.py <task.toml>` — must pass.
- [ ] **Both repos needed**: Verify the task genuinely requires reading both upstream and downstream repos (not just one).

### 5. Final Steps

- [ ] **Rename directory**: Move from `output/mining_candidates/<id>/` to `benchmarks/<suite>/<id>/`.
- [ ] **Implement verifiers**: Replace stub scripts in `checks/` with real grep/test patterns.
- [ ] **Write ground_truth.json**: Create provenance file with PR references and affected file lists.
- [ ] **Schema validation**: `python3 -m lib.eb_verify validate benchmarks/<suite>/<id>/task.toml`
- [ ] **Add to repo_versions.json**: Pin SHAs for the repos in `configs/repo_versions.json`.

## Promotion Decision

| Signal | Promote | Hold | Reject |
|--------|---------|------|--------|
| Confidence | high | medium | low |
| Fix scope | 2–20 files | 1 file or 20–30 | 30+ files |
| Ground truth | PR + commit | PR only | Neither |
| Reproducible | Yes | Partially | No |
| CRNT | Pass | — | Fail |

**Promote**: Move to `benchmarks/`, implement verifiers, add to task mix.
**Hold**: Needs more investigation. Add notes to `metadata.json` and revisit.
**Reject**: Not viable. Delete candidate directory or move to `benchmarks/_archived/`.
